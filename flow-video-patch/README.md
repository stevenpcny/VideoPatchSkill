## 使用

保持文件夹结构，把本目录放到接收电脑配置的Codex技能目录，或让其他助手先读[AGENT_ENTRY.md](AGENT_ENTRY.md)。具体安装位置按接收环境设置；本包不会自动安装到用户技能目录。

先读[安装说明](references/install.md)，自行安装Python、FFmpeg／ffprobe、NumPy与一种OpenCV Python发行包，然后从本目录运行：

```bash
python scripts/flow_patch.py doctor
python tests/smoke_test.py
python tests/security_test.py
python tests/qc_tools_test.py
python tests/color_pipeline_test.py
sh tests/ffmpeg_regression.sh
```

入口为[SKILL.md](SKILL.md)。本地处理不需要网络；安装依赖或使用外部生成服务需相应网络和账号权限。Flow生成由使用者自行完成。

未发布改动（下一版候选）：`flow_patch.py` 再提速且成片逐字节不变——`probe` 一遍解码并同时探测原片与返回片、成片校验各项并行、无关键帧遮罩缓存、融合与缩放贴回的逐元素运算按行多线程、恒等调色跳过；`fit_patch.py` 只转换裁切区。修正：FFmpeg 6.1 等旧版把全范围（yuvj）源片解码成有限范围、Reader 却按全范围解读，导致全范围源片对比度被压缩；现解码时显式声明范围（有限范围源片解码逐字节不变）。合成 4K 测试（4 核 Linux，FFmpeg 6.1）由 49.5 s 降至 25.4 s，缩放贴回 38.6 s 降至 25.2 s，输出与 v2.4 哈希相同；新增 smoke test_09。读取器提前结束时直接结束解码进程，不再白等 5 秒终止超时（返回片尾部有未用帧时，合成 4K 测试 50.8 s → 27.7 s；smoke 测试 146 s → 21 s）。新增可选分段多进程合成 `FLOW_SEGMENTS`（默认 1 不分段；码流与单进程不同，音轨与帧数整片校验；4 核机器无收益，多核工作机须实测），见[局域网工作机执行](references/remote-worker.md)；新增 smoke test_10、security 段数边界检查。

v2.4 处理提速与工作机：新增[局域网工作机执行](references/remote-worker.md)（用户本地档案启用，机器信息不入包）。`flow_patch.py`：`FLOW_ENCODE_THREADS` 控制 libx264 线程（默认 4，与旧版一致）；逐帧色彩转换按行多线程（`FLOW_PROCESS_THREADS`，结果逐值相同）；解码预读与编码写出后台线程；`merge` 仅把补丁区域转成 BGR，支持区外亮度在编码前与原片解码值一致（此前经 RGB 往返，越色域处可差数级）；编码器中途退出时报告其日志。合成 4K 测试（120 帧、60 帧带 1200px 多频段补丁）在 24 核 Windows 工作机由 128 s 降至约 55 s。不新增工具、依赖或编码器授权；`color_pipeline_test` 增加支持区外亮度一致性检查（9 项），`security_test` 增加线程参数边界检查（11 项）。
