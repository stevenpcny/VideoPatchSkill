# 用户指定的方案审批与反馈流程

仅当当前用户要求先看方案再合成，或明确沿用此偏好时应用；不是所有用户的默认审批要求。

- 原片检查后、制作正式 Flow 遮罩前展示适用方案；收到返回片先预检，再在正式贴回前展示 2–3 个有实质区别且可行的候选。明显不可行时报告原因，不凑候选数。
- 候选使用实际帧，包含原片/返回片并排、满替换区、羽化带、保留区、接缝位置及遮挡前后关系；显示首尾、最大运动、手/话筒/邻人交界，并给出首选及风险。静态图审批只批准方案，不代表动态质量通过。
- 遮罩边界、接缝位置、调色和最终导出须用户批准；将这些选择合并展示以减少往返。可自动完成元数据、定位、预检、候选图及批准范围内的检查片；批准前不做正式合成。已批准参数无需重复确认，实质改变边界/接缝/颜色时重新展示差异。
- 审片提供原片与成片并排及接缝示意；近景审看1080p，中远景审看4K。按人物在画面中的占比判断景别；混合景别采用更高要求。放大不代表新增细节，必须注明来源；最终尺寸另按任务约定。
- 先导出最易出问题的短窗口，获认可后跑完整检查片，再经最终导出批准生成交付文件并复核最终编码。低清代理或短片通过不代替完整最终文件验收。
- 每次具体反馈记录文件/版本、帧号或时间、用户原话、问题位置、原因假设、改动和验证状态。用户反馈、待验证假设、已验证通用经验分开；局部认可只覆盖对应区域和时段。
- 记录位置与格式按[成功案例与踩坑记录](experience-log.md)，在每次任务内及时落盘；不声称后台自动学习。明确的流程偏好可更新本机技能；技术经验经实际对照验证再提升为规则，不把单镜头坐标/阈值通用化。用户路径、姓名、素材和实际参数不写入技能发行包；线上发布另需授权。
