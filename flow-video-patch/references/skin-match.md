# 换头后身体露肤匹配

适用场景：只重新生成了头部，但新人物的肤色、年龄或族裔与原人物不同。补丁区外的脖子、手、前臂仍然是原片，颜色和新脸对不上。以下是一次通过实片验收的做法，经过抽象后整理；数值只说明量级，新素材要重新测量。

## 先选路线

| 情况 | 路线 |
|---|---|
| 新旧肤色差别小（LAB 各通道差约 3 以内） | 不处理身体，避免把接近肤色的衣服一起调坏 |
| 肤色差别明显，露肤面积小（脖子、手、前臂） | 本地调色：只平移颜色统计量，原片纹理、明暗和动作保留 |
| 肤色差别明显，露肤面积大或细节要变（手臂、腿、手型、年龄纹理） | 重新生成，或扩大补丁的连续区域；调色不能改变形状和纹理 |
| 发型体积和原片不同（例如蓬松卷发替换贴头短发） | 先单独扩大该人头部的生成范围和蒙块外扩，为新头发留空间，再做肤色匹配 |

## 本地调色的正确做法

1. **只调补丁没改过的像素。** 用"补丁结果减原片"的差值找出已被生成内容替换的区域（模糊后阈值约 10/255，限定在头部附近）。这些像素一律不再调色，否则重叠的那一段会被调两次，形成色带。
2. **目标颜色按接缝处的实际改动量来定，不要用脸颊。** 脖子一般比脸颊暗，用脸颊均值当目标会让脖子偏浅，下巴下方出现分界。正确做法是在生成区内、离接缝约 16–70 像素（4K 下）的范围取样。挑出同一批像素：原片中是皮肤，生成后仍是皮肤。逐像素计算 LAB 改动量，取中位数作为平移量。
3. **避开羽化带。** 贴回边缘的羽化带只被改了一半，在那里取样会低估改动量。先把生成区向内腐蚀，再取样。
4. **皮肤判定要排除三类区域：**
   - 用原人物脸部的色度（a、b 通道）建模，按马氏距离判定皮肤，再加亮度范围限制；
   - 用该人物躯干中段的衣服色度建模，凡是离衣服比离皮肤更近的像素一律排除（防止珊瑚色、米色衣服被当成皮肤）；
   - 整个头部掩码排除，避免在脸上调出斑块。按动作范围限定垂直区域，例如只取上半身，防止鞋、腿被误判。
5. **只做 LAB 平移加有限的亮度增益。** 增益限制在约 0.85–1.2；a、b 不做方差缩放，脸上的色度方差多半来自嘴唇和腮红。掩码先开运算去掉噪点，再做 2–3 像素高斯羽化。
6. **一组统计量用全片。** 每 2–3 帧抽一次样，汇总成一组参数，不要逐帧变化，否则会闪。

## 分割的边界

文字提示分割"手、手臂、脖子"这类小部位，在多人中远景画面里召回率很低，手还常被道具遮挡。更稳的做法：用人物整体掩码区分是谁的皮肤，再用上面的肤色/衣服色度模型找出露肤。

人物跟踪、分割模型或生成服务都不在本包默认白名单内。使用前按 [工具白名单与审批](tool-policy.md) 停止、核查，并取得用户明确同意。本包脚本目前不含自动肤色匹配功能；要在本地用 NumPy/OpenCV 新写处理步骤，同样属于扩展用途，先说明范围并取得批准。

## 必做检查

完成后按 [检查说明](verification.md) 的"融合性与匹配性检查"逐人核对，重点看以下三处：
- 下巴下方接缝两侧的颜色差；
- 同一人脸、脖子、手是否是同一种肤色；
- 衣服颜色是否被改动。

## 常见失败与原因

| 现象 | 原因 | 处理 |
|---|---|---|
| 下巴下方一条浅色带 | 目标取了脸颊色，或重叠区被调两次 | 改为接缝改动量；排除已生成像素 |
| 调色后脖子仍偏浅一档 | 取样落在羽化带 | 生成区先向内腐蚀再取样 |
| 衣服局部变色 | 衣服色度接近皮肤 | 加衣服色度模型；肤色差小的人不处理 |
| 脸上出现小斑块 | 生成几乎没改的脸部像素被当成身体皮肤 | 排除整个头部掩码 |
| 颜色随帧闪烁 | 逐帧统计 | 全片一组参数 |
