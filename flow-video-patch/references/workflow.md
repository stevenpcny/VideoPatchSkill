# 完整流程

## 1. 制定修补目标

读取原片和实际关键帧，明确人物、问题、源帧区间、嘴/麦克风的处理与输出。建立新工作文件夹，保留原片。查看镜头是否移动、人物是否转头/遮挡/交叉，决定固定框还是跟踪框。

```bash
python scripts/flow_patch.py inspect --source "source.mp4"
```

对眉眼修复，蒙块不能覆盖需要保留的嘴。对整头修复，蒙块覆盖问题区域，身份参考图以五官清楚且不相互矛盾为准；头发和肩领是否生成按目标选择。三视图只是可选身份参考，不是每次必需。

## 2. 准备人物裁切和蒙块

复制`assets/prepare-template.json`。原片中的crop可以是固定框或带绝对源帧号的线性关键帧。所有crop保持与上传尺寸一致的宽高比；蒙块坐标在上传尺寸中。必要时每帧记录一个关键帧，不依赖插值处理突变或遮挡。

`core`是实际待修段，`context_frames`默认24帧，前后保留无遮挡画面便于身份、动作和对齐。24帧不是固定1秒；时长取决于fps。首尾不足时脚本保留实际可用帧，**不重复边界帧**，报告记录实际`first`和`core_in_upload`。

```bash
python scripts/flow_patch.py prepare --config "prepare.json" --output "upload.mp4" --dry-run
python scripts/flow_patch.py prepare --config "prepare.json" --output "upload.mp4"
```

准备输出含所截区间的原音频重新编码为AAC；合成输出才复制整条原音轨。报告内首尾参照区与核心区使用精确帧号。

分别保存裁切画布、生成遮罩和最终融合遮罩；眼镜、手和衣袖交界等按 [局部补丁经验](patch-lessons.md)检查。检查最终编码的无遮挡首尾、蒙块是否一直覆盖问题区域、是否误盖嘴/手/乐器，以及人物裁切有无拉伸。跟踪crop能改变相机在局部画面中的位置观感，提示词应说明保持局部输入已有运动，不额外稳定或推拉。

此处的crop是工作画布，mask_regions是生成时要重建的区域；两者都不自动等于最终贴回遮罩。准备时记录这三类范围，避免后续将整块裁切背景一起覆盖回原片。

## 3. 分段与Flow生成

长片按实际所用Flow模式的输入时长/尺寸限制分段，不能把历史“8秒”当作所有模型硬上限。本地习惯以约8秒上传预算起步，其中包含前后参考。设fps为f，总预算为N帧，两侧参照各C帧，则可用核心不超过`N-2C`；如非正数先调整预算。相邻核心用不重叠的`[a,b)`、`[b,c)`，参考区允许重叠。

每段单独写prepare配置，记录源帧区间、实际上传起帧、裁切轨迹、身份参考与提示词。分段位置尽量避开急转头、遮挡切换和张嘴峰值；补丁接点仍需检查。多人按有效脸部像素和遮挡关系选择分别或共同生成；分别返回时各自记录参数。

使用者在Flow上传蒙块视频、身份参考及相应[提示词](prompts.md)。实际上传限制、模型能力和输出尺寸以当时界面为准。下载结果后保存原始生成文件，不覆盖它。多人可按实际脸部像素与遮挡关系比较单人或共同生成，并按人从候选中选优；不固定生成次数。技能包不包含自动Flow调用。

## 4. 核对时间，再核对空间

每份返回独立 inspect、配准和核对 frame_map；不能复用另一候选的映射。分别inspect源片与Flow结果。先用身体、手、乐器和背景动作比较帧序；只看脸不能证明同步。候选偏移可通过抽帧联系图或逐帧比较得到，但最终参数只录入已核对的对应关系。

返回宽高比变化时，先比较等比缩放、中心裁切或额外扩图等实际关系，用未改动身体/衣物核对，不直接拉伸成原画布。抽取trim片段用于比较时，重置PTS并保持原帧序，断言提取帧数与请求区间一致，防止工具补帧导致首帧重复、接点指标误判。面部比较不要被大片静止背景的平均误差稀释。

例如源核心`[48,120)`，上传实际从24帧开始，Flow完整保留上传帧序，则`generated_start=24`。若返回视频多出末尾3帧且前面同序，可只用已核对的对应索引；若少末帧，明确使用重复最后帧的`frame_map`，或以`null`保留原片，并审看边界。不能自动把全片拉长/压短。

复制`assets/merge-template.json`，从对应prepare复制crop轨迹和工作尺寸；多段/多人添加patch对象。全片坐标仍以原片为准。输出只替换target，其余时间沿用原画面。

可选辅助配准：

```bash
python scripts/fit_patch.py --config "merge.json" --patch 0 --output "merge-proposed.json"
```

它用未修区估计平移，并对相邻已观察帧平滑，再用多个时间点的参照估计一组固定BGR调色参数；在留出的采样帧误差未降低时不应用新调色。输出为建议，需审看。自动配准失败不会写出配置；调整时序、裁切、`fit_exclude`或手动仿射。fit不是人物跟踪、时间搜索或可靠性证明。

## 5. 选择贴回与融合

- 保护原嘴：alpha，上半脸区域；保护区和羽化必须经实际运动检查。
- 头部小幅变化：矩形或椭圆alpha，区域容纳原头和新头的全部轮廓。
- 下颌/脖子接缝反复明显：试连续整头到肩领/上胸，多频段融合。对比宽柔边alpha和多频段，不预设一种永远最好。
- 背景出现矩形边、亮度圈或纹理块：先看黑白遮罩及原/补丁/成片对照，判断是否误带入生成背景；比较缩小背景参与范围、人物前景并集和其他融合方式，而非反复加宽羽化。颜色/亮度分离仅在本镜头可验证时使用，检查墙面暗纹误入、头发漏选和逐帧闪烁；具体方法见[cases.md](cases.md)。
- 皮肤偏色：脸、耳侧、颈部和手共同取样审看，确认RGB/BGR、色彩矩阵与范围；对皮肤局部温和调整，两段使用一致逻辑，不全矩形染色或逐帧跳动校色。
- 大幅遮挡、人物交叉、头发超出裁切：重新裁切、逐帧细遮罩如需另用跟踪/合成工具，先停止该步骤，完成白名单扩展核查并获用户明确批准；本包基础几何不解决所有遮挡。

```bash
python scripts/flow_patch.py merge --config "merge-proposed.json" --output "patched.mp4" --dry-run
python scripts/flow_patch.py merge --config "merge-proposed.json" --output "patched.mp4"
```

先使用短源片或短target确认关键位置，再按最终参数从原始尺寸重新合成。仅缩短target不会缩短输出源片；想快速导出短片，先明确裁出工作源并同步重编号。不要把1080p预览放大成8K交付。多人从原片一次合成，避免修一次就重压一次。版本迭代仍从原片和原始返回重新导出，尽量合并处理后只做一次最终有损编码。独立补丁须记录是否已去黑边、是否已缩到贴回尺寸。

## 6. 复核与交付

按[检查说明](verification.md)对实际最终编码文件执行验收，复制并填写[视觉验收记录](../assets/visual-review-template.json)，不能只审看未编码帧或低清预览。发现接缝、重影、色跳或口型错位先修，再复查相关区间并正常速度看完整段；未完成的项目保留待审，不填pass。

交付成片、参数、`.report.json`和视觉记录，明确生成嘴/保留嘴、原音轨、源/生成帧数、缺帧策略和实际审看范围。独立补丁还应给同帧参照、摆放坐标/缩放、帧起点、遮罩含义和一次应用方式，并在原片局部做贴回验证；不得仅因补丁单独播放好看就判断能无缝贴回。项目配置含媒体路径，发给他人时改相对路径；不要附账号、令牌或无关个人目录。
