# 检查、交付与限制

## 工具使用清单

按 [工具白名单与审批](tool-policy.md)附实际使用的脚本、工具／库版本及构建、用途和许可证来源；清单外组件列出独立核查和用户批准依据。使用 [记录模板](../assets/tool-review-template.json)，填入后只在任务目录留存。视频脚本生成的 report.json 不覆盖整个智能体的所有调用，不能据此宣称自动拦截了清单外工具。

## 自动验证

每次prepare/merge生成旁置`.report.json`，检查实际输出尺寸、帧率、帧数和音频存在情况，再完整解码。merge核对第一条原音轨的编码载荷SHA256；视频重编码，不承诺原片未修区的编码像素完全一致。prepare音轨为选段后AAC重编码，不做原载荷一致性要求。

源片、输出和生成素材SHA256用于复现；配置文件记录crop、蒙块、target、映射、融合及固定颜色参数。输出失败时临时文件清理，不把未通过验证的视频当成功产物。

本包复验：`python tests/smoke_test.py`，用临时生成视频测试参照/蒙块、移动crop、保留嘴、多人贴回、多频段、明确尾帧重复、null回填、错误映射/重叠拒绝、输出防覆盖、全解码与音轨载荷；测试成功不等于任意Flow实片都能自动修好。

原音轨复制仍可能因画面帧数上限或 `-shortest` 少一个尾包；以载荷哈希为准，必要时辅查包数和末包。若需修正，复制已编码视频与完整原音轨重新封装到新文件，再完整验证；不要因容器比画面稍长就裁掉音频尾部。见 [局部补丁经验](patch-lessons.md)。

高级FFmpeg链路另跑`sh tests/ffmpeg_regression.sh`：6组合成不变量覆盖满alpha/非满alpha负对照、RGB16裁剪、局部效果与保护区、显式变速帧数和头区光影隔离。需先符合工具政策；它不替代主脚本测试或实片审看。

## 融合性与匹配性检查（必做）

补丁贴回后，必须对照原视频检查补丁与周边原片是否融为一体，而不只看补丁本身好不好看。每个补丁人物、每个分段都要单独查，结论写进交付报告。

1. **接缝颜色**：沿贴回边缘，分别取内侧（生成）和外侧（原片）几十像素宽的同类区域，例如下巴下方的脖子、额头发际。可比较 LAB 均值，但需记录颜色转换、取样区域和 ΔE 算法；OpenCV 的 8 位 LAB 编码距离不能直接当作标准 ΔE。数值只辅助定位，不能设一个通用阈值代替实际画面验收。抽首、中、尾和最大动作帧。
2. **肤色一致**：同一人的脸、脖子、手、前臂应属同一肤色；换人后肤色变化明显时按 [身体露肤匹配](skin-match.md) 处理，并复查。
3. **光照和质感**：补丁与原片的亮度方向、阴影、饱和度、噪点颗粒、锐度和压缩感要一致。生成区过度平滑或过度锐利同样是穿帮。
4. **几何和运动**：补丁和原身体的位置、比例、转头节奏一致，没有漂移、抖动、双轮廓或旧轮廓露出。
5. **时间稳定**：逐帧看接缝色差和补丁亮度，曲线不应跳变或闪烁；分段接点前后几帧单独看。
6. **遮挡层次**：手、道具、头发经过补丁区时，前后关系要正确。生成内容不能"透"到遮挡物前面。
7. **未改区不变**：合成前后未修区可在相同解码/颜色空间内核对；最终全画面有损重编码与位深转换会产生差值，不能要求编码后像素严格相等。结合差值、遮罩和原/修画面定位范围外改动；衣服颜色被局部调色波及属于失败。
8. **证据**：给出原片、补丁结果和差值或掩码叠加的并排放大图（每人至少 3 帧，含接缝区域），并写明哪些帧和区域看过、哪些未看。

不满足时先回到对应步骤（对齐、蒙块、融合方式、调色），不要用逐帧自动增益掩盖。

## 视觉验收的判定

复制[视觉验收记录模板](../assets/visual-review-template.json)到实际任务目录，记录最终文件、SHA256、源帧区间、修补目标、保护区、嘴部来源、独立对齐证据、每项审看范围、证据路径、问题和修订。最终编码全部修补帧联系图、原尺寸及放大边缘图、黑白遮罩检查和正常速度完整播放分别记载，不能互相代替；每个人、每个分段和每个独立补丁分别查。该记录由实际审看填写，不是自动无接缝检测器；JSON里写pass本身不构成证据。自动校验通过不提升视觉状态。

只有下面适用项目均实际检查通过、发现的问题已修复，才能标为`visual_pass`。任何适用项未执行记`not_run`，发现问题记`fail`；不适用项用`not_applicable`并写理由。只看关键帧或联系图而未播放，整体仍为`pending_visual_review`。允许交付清楚标记的待审候选与检查材料，但不能宣称“无接缝/无重影/口型已验收”。工具不能播放时如实留待审，不自动安装或换用清单外工具。

### 1. 核对实际输出及对齐

审查对象必须是本次最终编码文件，文件名/哈希和证据一致；不能只检查内存帧、旧版本、静态合成图或缩小预览。确认分辨率、宽高比、源/返回帧数、起点及显式映射，用未重建的身体、手、衣物验证时间和尺度。宽高比变化先识别裁切/缩放，不能默认拉伸。

用于分析的抽帧/trim应重置PTS、保持帧序，并断言数量等于请求区间。重复首帧、非预期补帧或错误索引会使接点评分失真。误差指标只作辅助，面部局部指标不能被大片静止背景平均稀释。

返回较短时，用首中尾的真实动作区分固定偏移、累积变速和突然缺帧；不能仅按时长比拉伸或默认补尾帧。眨眼任务按左右眼分别记录保留/修补事件，核对用户要求的单眼不同步情形。详见[高级合成诊断](advanced-compositing.md)。

### 2. 全修补帧巡检

对全部实际修补帧生成带源帧号的局部联系图，按段逐页查看，记录覆盖区间与页数。每张脸和边缘必须足够大；看不清时拆页，不能用极小缩略图声称已检查细节。标出异常帧，再从最终视频原像素抽帧复查。联系图不替代连续播放，也不能单独证明逐字口型。

首尾、最大横/纵位移、转头、快速动作、遮挡切换和肤色极值必须包含；对异常区间逐帧检查，不仅按每秒抽样。

### 3. 边缘、背景和遮罩检查

至少查看原像素100%及适当放大视图（如200%），并在完整构图中检查一次。不能只用缩至屏幕大小的全景判断小头部接缝。对照原片/生成片/最终成片，必要时用可切换或并排视图：

- 沿头顶、发丝、耳侧、鼻尖、下颌、脖子、衣领、肩部、袖口、手腕、手臂、话筒和指尖逐处检查亮边、暗边、断层、软糊圈、纹理突变及位置漂移。
- 用户指定细节窗口时，先核对裁图对应的真实部位与帧号；旧手指／袖口可在邻人衣料上留下肤色细线。按同帧原片／返回／成片对照判断来源，不只巡检目标人物头部，也不改查邻近的另一条衣缝。局部补丁的核心及完整启停边界均要逐帧复查。
- 查看整个融合区及其周围一圈背景，尤其是矩形角、墙面暗纹、亮度圈和生成背景变平滑形成的轮廓；不要只盯脸。
- 黑白查看最终遮罩，并以叠色视图对照原/新轮廓并集。检查头发/下颌漏选、背景误选、遮挡层次、羽化穿过嘴/眼睛、保护区漏出旧脸；随时间检查遮罩闪烁。几何遮罩或颜色阈值都不能假定为语义正确。
- 独立补丁须在原片局部按交付坐标、缩放和遮罩实际贴回后再审看；黑白/灰阶含义、一次应用、是否已烘焙融合必须说明，防止重复羽化或重复套遮罩。

整幅叠加原/修画面会故意产生“双轮廓”，只能辅助找位移；必须在最终正常合成画面中确认是否真的重影。

手写合成链路须测核心/羽化/外部/保护区的实际alpha数值，并验证完整柔边位于画布内。对头周暗圈，另查低频调色是否带回原头空间阴影；不透明遮罩并不排除这一原因。对异常轮廓区间查全部帧，按[高级合成诊断](advanced-compositing.md)隔离来源。预编码保护区像素相同不等于最终编码无损。

局部修补或多人交界还需按[多人交界与局部借用](overlap-and-local-donors.md)检查后层旧前景轮廓、新增饰物、供体配准及计算画布边界。耳垂／扣子小窗检查与完整头部检查分别记录，不能把前者的全帧计数当成后者已做。

### 4. 重影与分段接点专项

对每个接点、修补起止边界检查其前后至少约0.5秒的所有帧（按实际fps换算，片边界不足则查可用帧）。重点比较头部位置/比例、眨眼开合、口形、眼镜、话筒与肤色；眨眼闭合直接切到睁眼、收口接张嘴等过渡，需要慢速和正常速度确认，不能只依赖静态相似分数。

在最终画面中找旧鼻尖/下颌露出、双眼睛/双镜框、两层嘴唇或牙齿、双话筒轮廓和颈部重叠。检查羽化是否穿过新旧五官、时间淡变是否叠脸、缺帧补法是否造成局部停顿。不能用给脸加长交叉淡变来掩盖未对齐；优先修时序、空间、轮廓覆盖、遮罩或换合适接点/备选片段。修完后重新检查整个接点窗口。

### 5. 肤色与解码颜色

比较两段首中尾、接点及不同光照姿态：脸、耳侧、脖子、手是否协调；有无偏青/绿、过粉、过曝、分段色跳。参考截图只提供色彩方向，不能把不同曝光RGB当作绝对一致目标。

区分RGB/BGR、SDR/HDR、矩阵、传递函数、原色及full/limited范围。修改或补齐标签后检查实际解码RGB与视觉效果，不能以元数据正确代替像素解释正确。皮肤局部调色应检查是否误染嘴唇、眼镜、白衣、头发和背景；固定校色及多频段融合也需审看，不用逐帧随机增益掩盖问题。

高位深链路检查最暗头发、高亮牙齿和镜片，排除残差溢出色点。QuickTime/访达等播放器偏色须在用户实际播放器对照原片；相同标签和解码统计不足以证明播放一致，改编码器仍遵循原有审批边界。

清晰度比较同场景、相近脸尺寸的眉眼、眼镜、嘴唇、皮肤和颗粒；区分偏软与过锐，再选小幅局部调整。检查边缘光晕及运动中锐度闪烁，不能只以锐度分数判通过。实际调节与再次有损编码情况记入记录。

### 6. 正常速度播放与回归

在完整构图和足以看清脸部的局部视图中，正常速度播放全部修补段及其接入原片的边界，确认边缘不闪、没有运动重影、表情/眨眼连续；有演唱/对白时带原声检查实际词句口型、换气和收音。必要时对快速动作慢放或逐帧辅助，但不能用慢放代替正常速度检查。

修改遮罩、融合、接点、帧映射、肤色或编码后，更新最终文件哈希并重做受影响的帧/边缘/接点/颜色检查，再正常速度播放整段；原音轨和完整解码也应对最终导出复核。不复用旧版本的pass作为新版本验收证据。

可选生成1080p预览（从已合成输出缩小，不作为高分辨率母版来源）：

```bash
# 用 --copy-unpatched 交付时，另在实际播放器/剪辑软件中拖动并播放各复制块与渲染块的交界
ffmpeg -n -protocol_whitelist file -i patched.mp4 -vf "scale=1920:-2" -c:v libx264 -crf 20 -c:a copy preview.mp4
```

竖屏或小源片自行按合理目标尺寸调整，不为预览无意义放大。带`-n`防止覆盖。

## 限制与常见处置

- Flow改动黑块外区域：只取所需局部，原身体/手/背景来自原片。
- 首尾双脸：整段替换先关闭fade；局部目标接回原脸要另选接点，不保证关闭淡变就没有跳变。
- 旧鼻尖/下颌露出：扩大覆盖新旧运动的并集，把羽化移出皮肤轮廓，必要时更换连续区域。
- 换人后脖子/手与新脸肤色不符、下巴下方出现色带：见 [身体露肤匹配](skin-match.md)，用接缝改动量而不是脸颊颜色作为目标，并排除已生成像素。
- 色偏随帧变化：固定调色只能部分解决；检查光线或分段手动处理，不用自动逐帧抖动增益掩盖。
- 矩形/光圈接缝：优先诊断生成背景纹理和亮度是否被带回，检查实际遮罩误选；只加宽羽化可能扩大问题。具体方案见[cases.md](cases.md)，不是一律换成更大矩形。
- 帧数不同：先找真实对应，显式映射；重复末帧只适用于已确认的边界差异，不能套到中间缺帧。
- 场景重复/背景静止：ECC相关性高仍可能对错时刻，时间要用动作核对。
- HDR/10位/旋转/VFR：本包会拒绝，应先明确转换方案。转换后重新测量时间及空间。
- 多人交叉、手遮脸、复杂遮挡：矩形/椭圆和关键帧不是语义分割；如需外部跟踪/逐帧遮罩工具，先停止该步骤，按白名单扩展流程核查并获批；本包未承诺自动处理。
- 音轨不兼容MP4：用支持该音轨的MOV/MKV，或明确选择转码；脚本不会悄悄改原音频。
- 没有自动生成、模型下载、自动人物识别或口型修复；依赖接收者能力和实际使用工具。

## 交付文字模板

“已输出〔文件〕，〔尺寸/fps/帧数〕，使用〔范围，如上半脸/整头至肩领〕，〔原嘴保留/Flow嘴参与〕，原音轨〔实际结果，如第一条原音轨复制并通过载荷哈希校验〕。时序采用〔映射说明〕。技术验证〔通过/未通过〕；融合性与匹配性检查〔每人接缝颜色、肤色一致、遮挡与时间稳定结论；如测ΔE则附算法与取样证据〕；视觉状态〔visual_pass/pending_visual_review/visual_fail〕。实际完成〔全帧覆盖区间、原像素/放大边缘、遮罩、接点窗口、肤色、正常速度播放及声音等〕；未完成〔缺项〕，仍有〔问题〕。附参数、技术报告和视觉验收记录。”
