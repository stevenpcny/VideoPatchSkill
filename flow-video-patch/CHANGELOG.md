# 版本记录

按新到旧排列。两条历史发版线（仓库线、本地线）在 v2.0 合并，其 v1.4、v1.5 编号指不同内容，按线别标注。

## v2.6

经包所有者批准新增三项可选组件，均默认不改变既有行为，范围记录在 `TOOL_POLICY.json` 的 `optional_components_owner_approved`。

- 可选编译内核 `native/`（Rust，仅标准库，经 `ctypes` 调用）：色彩转换、补丁外色度均值、融合与缩放贴回。首次使用前与 NumPy 逐位比对，不一致即停止；`FLOW_KERNELS=auto|native|numpy`。合成 4K 测试 Python CPU 约 28 s → 18 s，总耗时约 18.4 s → 13.7 s（快速编码），输出逐字节相同。见[可选编译内核](references/native-kernels.md)。
- 可选硬件编码 `FLOW_VIDEO_ENCODER=h264_nvenc|h264_qsv|h264_amf`：检查用导出可直接使用；交付与 Flow 上传须 `FLOW_HW_DELIVERABLE=1`（已在该机比较画质）。测试环境无显卡，未实测。
- 远程执行脚本 `scripts/remote_run.py`：`check`／`push`／`run`／`pull`，只用 ssh 连接本地档案中的单个工作机，传输两端比对 SHA-256，不覆盖、不删除。
- `doctor` 显示编译内核状态、编码器与构建中可用的硬件编码器。
- 测试：smoke 17、security 15、remote_run 2；CI 在三个平台分别以 NumPy 与 Rust 内核运行全部测试。

## v2.5

处理提速（完整导出与 v2.4 逐字节相同）、检查用导出、可选分段合成、三平台 CI 及若干正确性修正。不新增工具、依赖、编码器或服务授权。

- 提速：`probe` 一遍解码并同时探测原片与返回片；成片校验各项并行；无关键帧遮罩缓存，静态遮罩／仿射只校验首帧；融合与缩放贴回的逐元素运算按行多线程；恒等调色跳过；`fit_patch.py` 只转换裁切区。读取器提前结束时直接结束解码进程，不再白等 5 秒终止超时；读取器在帧时间戳规整的文件上直接寻址到起点。合成 4K 测试（4 核 Linux）49.5 s → 25.4 s（同尺寸）、38.6 s → 25.2 s（缩放）、50.8 s → 27.7 s（返回片尾部有未用帧），输出哈希与 v2.4 相同。
- 检查用导出：`merge --frames START:END` 只导出指定原片帧（配置帧号不改），`--preview` 用 ultrafast 编码；报告标为不可交付；检查运行缓存未变输入的探测结果。1080p 2 分钟片检查片尾 30 帧由整片合成 125.9 s 降至 3.1–10.2 s。
- 可选分段多进程合成 `FLOW_SEGMENTS`（默认 1 不分段；码流与单进程不同；4 核机器无收益，多核工作机须实测）。
- 交付编码可调：`FLOW_CRF`（默认 17）、`FLOW_X264_PRESET`（默认 fast），实际值记入报告命令。
- `fit_patch.py --motion euclidean|affine`：可选旋转／缩放配准，线性部分变化受 `--max-linear-change`（默认 0.08）约束；默认仍为平移。
- `qc_tools.py seam`：按 [返回片贴合度预检](references/return-fit-assessment.md) 第 5 条，用与合成相同的补丁、遮罩计算过渡带加权高低频差，供候选比较。
- 淡变可分别设首尾：`fade_in_frames`／`fade_out_frames`（`fade_frames` 仍同时设两端）。
- 报告与终端 `NOTICE`：源片为 4:2:2／4:4:4 时说明输出为 4:2:0；多条音轨只保留第一条；字幕、数据、附件流不进入输出。
- 修正：FFmpeg 6.1 等旧版把全范围（yuvj）源片解码成有限范围、Reader 却按全范围解读，导致对比度被压缩；现显式声明范围。毫秒时间基（如 MKV）的恒定帧率源片不再被误判为变帧率。脚本自行以 UTF-8 输出，Windows 不再需要 `PYTHONUTF8=1`。
- 测试与 CI：smoke 16、security 13、qc_tools 5 项；GitHub Actions 在 Linux／macOS／Windows 运行五套合成测试、doctor 与包内哈希检查；`.gitattributes` 关闭换行转换；security 中 Windows 不可能发生的改名竞态测试在 Windows 上跳过并注明原因。

## v2.4

处理提速与工作机：新增[局域网工作机执行](references/remote-worker.md)（用户本地档案启用，机器信息不入包）。`flow_patch.py`：`FLOW_ENCODE_THREADS` 控制 libx264 线程（默认 4，与旧版一致）；逐帧色彩转换按行多线程（`FLOW_PROCESS_THREADS`，结果逐值相同）；解码预读与编码写出后台线程；`merge` 仅把补丁区域转成 BGR，支持区外亮度在编码前与原片解码值一致（此前经 RGB 往返，越色域处可差数级）；编码器中途退出时报告其日志。合成 4K 测试（120 帧、60 帧带 1200px 多频段补丁）在 24 核 Windows 工作机由 128 s 降至约 55 s。不新增工具、依赖或编码器授权；`color_pipeline_test` 增加支持区外亮度一致性检查（9 项），`security_test` 增加线程参数边界检查（11 项）。

## 本地线 v1.8／仓库线 v1.5.1

本地线 v1.8（仓库线同内容为 v1.5.1）修正 flow_patch.py 色彩管线：旧版经 FFmpeg 隐式转换解码会整体压暗约 1 级，并以无标签 BT.601 编码，播放器按 709 解读时整帧偏色，多轮合成会累积。现按源标签（709/601、tv/pc）在脚本内精确换算，用码流元数据写入色彩标签（不再触发隐式转换），不支持的矩阵直接拒绝。新增 `python tests/color_pipeline_test.py`（8 项）。不新增工具或授权。

## 仓库线 v1.4 融合与匹配

新增 [身体露肤匹配](references/skin-match.md)：换头后脖子、手等身体露肤的处理经验，要点是以接缝处的实际改动量为调色目标、已生成的像素不再调色、排除衣服和头部。[检查说明](references/verification.md) 新增必做的"融合性与匹配性检查"：补丁必须和原视频比对接缝颜色、肤色一致、光照质感、运动、时间稳定和遮挡层次。本版仅更新文档，处理脚本和测试与 v1.3 字节一致。
