# 第二轮：正式落地与继续提速

后续测量与有界帧缓冲复用见[第三轮报告](frame-pools.md)。下文保留第二轮当时的结果。

P0已通过[PR25](https://github.com/stevenpcny/VideoPatchSkill/pull/25)合并：Windows Reader读取管道、精确固定调色查找表。Windows本地NumPy/native各六套回归通过，三平台×两内核CI全部成功。没有改动历史发行ZIP或安装技能。

P1采用多频段金字塔工作区复用。基于P0固定版本的五对完整CLI实验，中位数 **19.814→17.702秒，节省10.66%**；每对实际编码MP4均逐字节一致。正式实现另一次完整CLI为17.677秒，输出仍匹配原基准；后者仅是一条生产实现确认，不代替五对性能结果。

## 候选及去留

相同工作机、Rust内核和四线程，单因素测试每次120帧、五对交替AB/BA；质量检查与计时分开。此处阶段时间不能与完整流水线等待时间直接相加。

| P1 | 复用OpenCV金字塔临时目的数组 | +29.00% | 完整CLI再节省10.66%，移入正式实现 |
| P1 | 小层单块、大层4分片 | +5.84% | 未达到阶段15%门槛，保留原调度 |

P2/P3尚无达到门槛的实现。本轮没有引入有帧所有权风险的输出缓冲池，没有更换像素布局、减少金字塔层数或省略完整校验。后续若继续研究，应单独测量SIMD/ROI转换等新方案，不能把当前微小收益包装成已达到目标。

## P1正式实现合同

- 使用原来的OpenCV算法、默认边界规则、层数和float运算；仅向金字塔算子提供可复用目的数组，每次使用前完整覆写。
- 工作区属于调用线程；同一线程仅保留一种形状与层数组合，变化即替换。各数组按种类、角色、层级、尺寸和dtype区分。
- 每个调用线程缓存的数组载荷不超过32MiB；超出预算的槽位沿用原分配路径。不是全进程RSS上限；分段进程或并发调用线程各有预算。
- 输出uint8结果始终新建，不进入缓存；后续帧不得改写已返回结果。alpha不创建该工作区。保持现有线程分片并行。
- smoke31对比零缓存路径，覆盖1–6层、fade0/0.13/0.5/1、低预算回退、旧结果所有权及双线程缓冲隔离。

3840×2160、24fps、240帧、640×640多频段补丁，非恒等调色；输入与上轮完全相同。每次新Python进程、空任务probe缓存、暖OS缓存；包含预取、完整输入核验、渲染、输出严格解码、原音轨、哈希、报告及发布。

## 非目标与内存

192×128、640×640及1920×1080的alpha/多频段算子均做独立旧新对照，输出一致。多频段分别约快15.7%、23.0%、6.6%，短测含工作区首次构建；不推广为完整任务速度。192×128 alpha最初仅3帧的测量出现约6%退化，按规则加长到500帧×五对并共用相同工作线程，差异降为约1.69%，低于5%门槛；alpha运算路径未更改。

单次正式CLI的父Python进程峰值工作集255143936→260190208字节，约增加4.8MiB。它是父进程的实际峰值，不是进程树峰值；不能用32MiB数组预算代替系统测量。尚未测长片多人、冷OS缓存或10bit/HDR，不声称这些场景已有收益。

## 复跑与证据

[机器可读证据](evidence/pipeline-second-round.json)保存所有阶段、完整CLI对次、生产确认、内存、短测与复测，以及失败排除说明。生产实现必须完成两内核本地完整回归与三平台CI后合并；最终结果以对应PR记录为准。

实验工具基于固定P0 `71d7029`：在独立工作树中使用本轮的 `top5_experiments.py`、`next_perf_experiments.py`，保留该工作树生产脚本不变，再运行：

```powershell
python tools/next_perf_experiments.py --out NEW_STAGE_RESULTS --pairs 5
python tools/top5_experiments.py --mode combined --source SOURCE.mp4 --returned RETURN.mp4 --native-dir flow-video-patch/native --out NEW_CLI_RESULTS --pairs 5 --selected next:blend_buffers
```

`passthrough_experiment.rs`仅是追加到既有native源码后、用已核查的Rust标准库工具链本地编译的测量扩展；编译产物不分发、不加载到生产路径。发布读取上界由 `publish_cost_probe.py` 单独测量，产物校验后只删除自己新建的复制文件，原视频不改写。
